# Subculture Calendar

원신·붕괴: 스타레일·젠레스 존 제로·명조·명일방주: 엔드필드 일정을 표시하는 캘린더입니다.

## 실행

Node.js 22 이상과 pnpm이 필요합니다.

```powershell
pnpm install
pnpm dev
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 같은 Node 서버에서 Vite와 `/api/calendar`를 제공하므로 별도 백엔드 실행이 필요하지 않습니다.

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm start
```

`pnpm start`는 빌드된 `dist`를 제공하며 수집 API도 함께 실행합니다. 정적 HTML만 배포하면 수집 API는 동작하지 않습니다.

## 전역 폰트 테스트

`src/styles/fonts.css`의 `--font-sans` 한 줄을 수정하면 제목·캘린더·버튼·입력창에 함께 적용됩니다. 폰트 목록은 왼쪽부터 사용하며, 해당 폰트가 없거나 글자를 지원하지 않으면 다음 폰트로 대체됩니다.

- 시스템 폰트: 설치된 폰트 이름을 목록 맨 앞에 지정
- 로컬 폰트: `public/fonts/`에 파일을 넣고, 설정 파일의 `@font-face` 예시 주석을 해제한 뒤 파일 경로와 폰트 이름을 수정. `--font-sans` 맨 앞에도 같은 이름을 지정
- 외부 웹폰트: 공급자가 제공하는 CSS `@import`를 설정 파일 맨 위에 추가하고 폰트 이름을 지정

일반 폰트는 사용하는 굵기별로 `@font-face`를 추가하고, 가변 폰트는 파일이 지원하는 범위에 맞춰 `font-weight`를 지정합니다(예: `100 900`).

`pnpm dev`에서는 저장 즉시 반영됩니다. `pnpm start`에서는 `pnpm build` 후 브라우저를 새로고침해야 합니다. 브라우저 개발자 도구의 실제 렌더링 폰트 항목에서 한국어와 영문에 적용된 폰트를 확인할 수 있습니다.

## 구현 범위

- 오늘 이동, 게임·일정 종류 필터, 제목 검색
- 선택한 게임·일정 분류는 브라우저 localStorage에 저장하여 재방문·새로고침 시 복원(전체 해제 포함). 검색어·선택 날짜·수집 데이터는 저장하지 않음
- 종료되지 않은 일정의 가장 이른 시작일부터 전체 일정의 가장 늦은 실제 종료일까지 가로로 표시. 필터에 맞춰 범위 재계산, 진행 중·예정 일정이 없으면 빈 상태 표시
- 게임별로 이벤트·픽업·엔드 콘텐츠·버전 행을 구분하고 모든 일정 막대에 분류 배지 표시
- 버전은 전환일 칸을 새 버전에 배정해 한 줄로 배치. 이전 버전 막대의 표시 끝만 다음 버전 시작 전날로 제한하며 실제 종료 시각·상세·종료 집계는 유지
- 높이 52px의 기간 막대, 같은 게임·분류에서 날짜가 겹치면 추가 행 배치
- 좌측 분류와 상단 날짜 고정, 앞쪽/뒤쪽 날짜 이동 버튼, 오늘 위치로 스크롤 복귀
- 최초 표시는 선택 날짜에 애니메이션 없이 배치. 필터·수집 결과로 범위가 바뀌면 보고 있던 날짜 위치를 유지하며 범위 밖은 경계로 제한. 날짜 선택·오늘·앞뒤 이동 버튼에만 이동 애니메이션 적용
- 상단 종료 일정 행에서 한국 시간의 실제 종료일별 개수 집계. 종료 표시나 목록에 마우스가 올라가 있는 동안 같은 날짜의 게임·분류·제목·종료 시각 목록 표시. 클릭 고정과 닫기 버튼 없이 영역을 벗어나면 해제, 목록의 일정 클릭 시 상세 열기
- 종료 목록은 해당 종료 표시 바로 아래에 배치하고 화면 좌우 여백에 맞춰 위치와 폭 조정. 스크롤 영역의 잘림을 피하도록 body 포털에 표시하며 CSS Anchor Positioning 지원 브라우저 필요
- 종료 집계는 게임·분류·검색 필터와 연동하며 42일 기본값 버전도 종료 집계에 포함하고 근거 표시. 이전 캐시의 시작 시점만 있는 버전은 제외. 자정 종료는 실제 종료 날짜에 집계(기간 막대는 전날까지 표시)
- 종료 목록 오른쪽 위에 가장 가까운 미종료 일정의 남은 기간 표시. 24시간 이하 HH:MM, 그 외 남은 완전한 일수 표시. 30초마다 및 탭 복귀 시 갱신
- 종료 표시·목록의 강조색: 7일 이상 흰색, 3일 초과~7일 미만 노란색, 3일 이하 붉은색. 이미 종료된 일정은 검은색에 가까운 회색 배경과 ‘종료’ 표시
- 날짜 선택 시 해당 날짜 일정 표시, 일정 클릭 시 완료 토글, `⋯`에서 기간과 출처 표시
- 아시아 서버 기준, 한국 시간(Asia/Seoul) 표시
- 다섯 게임 독립 수집, 15분 캐시, 마지막 성공 결과를 `.cache/`에 저장
- 수집 실패 시 이전 데이터와 상태 표시, 예시 일정 자동 대체 없음

## 완료 체크

일정 바·날짜 목록·종료 목록을 클릭하면 완료 상태를 토글합니다. 완료 일정은 체크와 반투명 스타일로 표시하며, `⋯` 버튼에서 상세를 확인합니다. 버전은 완료 대상에서 제외합니다. 완료 기록은 같은 브라우저에 저장하고 다른 탭의 변경도 반영합니다. 새 회차에는 이전 완료 기록을 이어받지 않습니다. 종료 후 180일이 지난 기록은 복원·저장 시 정리합니다.

종료 표시는 선택한 게임·분류의 전체 일정으로 판정하며 제목 검색으로 미완료 과제를 숨겨도 전체 완료로 처리하지 않습니다. 모든 대상이 완료됐고 그룹의 모든 일정이 아직 종료 전이면 초록색으로 표시합니다. 이미 종료된 일정은 기존 회색을 유지합니다. 브라우저 저장이 실패하면 현재 체크를 유지하며 저장 실패 안내를 표시합니다.

## 수집 관리자

주소창에서 `/admin`으로 직접 이동합니다. 메인 페이지에는 관리자 링크를 표시하지 않습니다.

- **확인 항목**: 기간 누락 공지, 본문 수집 실패, 영문 대체 일정, 42일 기본값·종료 시각 수집 누락 버전, 수집 범위 제한을 표시. 게임·처리 상태·제목으로 필터 가능
- 항목을 선택해 **원문 확인**과 수집 본문을 확인하고 메모와 함께 **처리 완료 / 제외**로 기록. 기록은 **미처리로 되돌리기** 가능
- 영문 일정·기간 수집 누락 버전은 **일정 보정**으로 제목·분류·기간·표시 언어를 수정. 제외된 공지는 **이 공지에서 일정 추가**로 확정한 기간을 수동 입력. 하나의 공지에 기간이 여러 개면 일정별로 추가하며, 저장 시 공지는 처리 완료로 표시
- **전체 일정**에서 수집된 일정과 수동 일정을 편집하거나 캘린더에서 숨길 수 있음. 기존 영문 대체 일정이 있으면 새 일정 추가 대신 해당 일정을 보정해 중복 방지
- 시간은 **한국 시간(UTC+9)**으로 입력하고 초 단위까지 보존. 종료는 시작 이후여야 하며 HTTPS 출처 URL 필수
- **보정 해제 · 원본 복원**은 수집 원본으로 복원. **추가 일정 제거**는 수동 추가한 일정만 제거
- **원본 재수집**은 15분 캐시를 건너뛰고 모든 게임을 수집. 수집 실패 시 마지막 성공 데이터 유지. 수동 보정과 처리 기록은 덮어쓰지 않음

관리 데이터는 프로젝트의 `data/admin.json`에 저장하며 재시작 후에도 유지됩니다. 보관 시 이 파일을 함께 백업하세요. `.cache/`와 별도로 관리하며 동시 저장은 직렬 처리하고 임시 파일을 원자적으로 교체합니다.

처리 완료·제외는 확인 기록이고, 원본 제공자의 ‘일부 확인 필요’ 상태나 실제 수집 범위를 바꾸지 않습니다. 일정 보정은 캘린더 출력에 적용됩니다. 기간 누락 진단은 공지 단위로 묶일 수 있어 확인 항목 수와 누락 이벤트 수는 다릅니다.

관리자 페이지는 로그인 없이 **IP 허용 목록**으로 접근을 제한합니다. `server/.env`의 `ADMIN_ALLOWED_IPS`에 접속할 클라이언트 IP를 쉼표로 구분해 입력하면 `/admin` 및 `/api/admin`의 모든 하위 경로에 적용됩니다. 예: `ADMIN_ALLOWED_IPS=127.0.0.1,::1,192.168.0.20`. 로컬 접속도 목록에 포함해야 하며, 변수가 없거나 비어 있으면 관리자 접근을 모두 차단합니다. IPv4·IPv6를 지원하고 IPv4 매핑 주소는 IPv4와 동일하게 비교합니다. IP가 아닌 값이나 CIDR은 거부합니다.

서버는 기본적으로 `HOST=0.0.0.0`으로 외부 연결을 받으며 다른 PC에서는 `http://서버IP:5173/admin`으로 접속합니다. `HOST`는 서버의 수신 주소이고 `ADMIN_ALLOWED_IPS`는 접근을 허용할 클라이언트 주소입니다. 직접 연결은 실제 연결 IP를 검사하고, `TRUSTED_PROXY_IPS`에 등록된 프록시의 연결에서만 `X-Forwarded-For`의 단일 IP를 사용합니다. 신뢰 프록시의 IP 헤더가 누락되거나 여러 주소이면 관리자 요청을 차단합니다. 관리자 변경 요청은 JSON 형식과 동일 출처 또는 `CORS_ALLOWED_ORIGINS`에 등록된 출처를 검사합니다. 설정 변경 후에는 서버를 재시작해야 합니다. 외부 공개용 인증·권한 기능은 포함하지 않습니다.

## 데이터 경로와 한계

HoYo 3종은 한국어 구조화 API `/mihoyo/{genshin|starrail|zenless}/calendar?lang=ko-kr`를 우선 유지합니다. 한국어 공식 인게임 공지 `announcement/api/getAnnContent`(아시아 서버·uid=0)를 추가 대조하여 기간이 비어 있는 이벤트와 예정 픽업을 보완합니다. 공지 게시 기간을 일정 기간으로 사용하지 않으며, 본문에 명시된 기간과 확인된 버전 시작만 사용합니다. 현재/예정 목록 전체를 보장하지 않고 기간 0/null·이미지 전용·상시 항목은 관리자 확인 대상으로 남습니다. 버전은 한국어 점검 공지 API 본문을 파싱합니다.

명조는 한국어 공식 CDN `G152/kr/ArticleMenu.json`과 `article/{id}.json`, 공식 네이버 라운지 28번 게시판의 JSON API를 사용합니다. 최근 100일, CDN 최대 80개·라운지 최대 8페이지를 조회합니다. 라운지의 offset은 항목 수가 아니라 0부터 시작하는 페이지 번호입니다. 게임 관리자 글만 수집하며 한국어 본문에 명시된 날짜와 버전 점검 종료를 연결합니다. 영문 대체를 제거했고 이전 캐시의 영문 항목도 표시하지 않습니다. 이미지 전용 기간과 명조 세 엔드콘텐츠의 공개되지 않은 반복 기간은 추정하지 않습니다.

엔드필드는 한국어 공식 뉴스 CMS 목록·상세 API를 우선 유지합니다. 최대 3페이지·최근 100일 중 최대 20개 관련 공지를 수집하고 API 실패 시 공식 웹페이지로 복구합니다. Asia UTC+8 기간을 사용합니다. 개별 공지 본문에 적힌 버전을 점검 종료와 연결하며, “버전 업데이트 전까지”는 다음 공식 점검 시작이 수집됐을 때만 연결합니다. 날짜만 발표된 버전 경계와 42일 기본값을 이벤트 종료 시각으로 사용하지 않습니다. 상시 개방과 특별 허가 헤드헌팅 3회 종료 같은 조건부 기간은 달력 종료일이 아니므로 별도 확인이 필요합니다. 엔드콘텐츠는 요구 범위에서 제외합니다.

버전 기간은 명시된 종료 시각 → 다음 버전 점검 시작 → 다음 버전 공개 날짜 → 시작 시각 + 42일 기본값 순으로 적용합니다. 기본값은 막대·상세·종료 목록에 `42일 기본값`으로 표시하고 관리자 확인 항목에 남깁니다. 단축 버전도 공지에서 확인한 기간이 우선합니다. 날짜만 공개된 경우 한국 시간 00:00을 날짜 경계로 사용하며 실제 종료 시각으로 취급하지 않고 날짜만 표시합니다. 정확한 시간 수집 시 교체됩니다. 점검 종료는 공지의 예정 시각이며 실제 조기 종료/연장을 자동 감지하지 않습니다.

데이터 연결 패널의 ‘일부 확인 필요’는 기간 누락 또는 버전 파싱 미지원 등을 뜻합니다. 제외 항목 수는 파싱 항목/공지 수이며 고유 이벤트 누락 개수와 같지 않습니다. 비공식 API 및 공식 내부 CDN의 구조 변경에 따라 어댑터를 수정해야 할 수 있습니다.

```text
tests/calendar.test.ts  날짜 경계·행 배치·수집 파서 테스트
```

## 환경 설정

환경 파일은 프론트와 서버로 분리합니다. 루트 `.env`는 Vite가 읽는 프론트 설정이고, `server/.env`는 Node 서버가 읽는 서버 설정입니다. 각각 `.env.example`, `server/.env.example`을 참고합니다. 실제 `.env`와 모드별 환경 파일은 Git에서 제외하고 예제 파일만 공유합니다.

프론트의 `VITE_API_BASE_URL`이 비어 있으면 현재 사이트와 같은 주소로 API를 요청합니다. 별도 API 서버를 배포할 때는 `https://api.example.com`처럼 경로 없는 서버 주소를 지정합니다. 캘린더·관리자·로그 요청 모두 이 주소를 사용합니다. `VITE_` 변수는 브라우저에 공개되므로 비밀값을 넣지 않습니다. 프론트 변경은 개발 서버 재시작 또는 재빌드·재배포 후 반영됩니다.

서버는 실행 디렉터리와 관계없이 `server/.env`를 읽으며, 이미 지정된 프로세스 환경 변수가 우선합니다. `CORS_ALLOWED_ORIGINS`에는 프론트의 출처를 쉼표로 구분해 입력합니다. 와일드카드는 지원하지 않습니다. 등록한 출처의 API 요청과 필요한 OPTIONS 요청을 허용하고, 관리자 API는 별도로 IP 제한을 적용합니다. 같은 출처의 로컬 요청은 별도 CORS 등록 없이 사용할 수 있습니다.

```powershell
$env:PORT = '5173'
$env:HOYO_API_BASE = 'https://api.ennead.cc/mihoyo/'
$env:WUWA_KR_CDN_BASE = 'https://hw-media-cdn-mingchao.kurogame.com/akiwebsite/website2.0/json/G152/kr/'
pnpm dev
```

## Pages와 VM 분리 배포

Cloudflare Pages의 빌드 환경 변수에 `VITE_API_BASE_URL=https://api.example.com`을 지정하고 다시 배포합니다. VM에는 `server/.env`를 별도로 만들고 다음과 같이 설정합니다. API 도메인과 관리자 접속 공인 IP는 실제 값으로 교체합니다.

```dotenv
PORT=5173
HOST=127.0.0.1
ADMIN_ALLOWED_IPS=203.0.113.20
CORS_ALLOWED_ORIGINS=https://subculture-calendar.pages.dev
TRUSTED_PROXY_IPS=127.0.0.1,::1
```

VM의 Nginx에서 API 서버로 전달하는 헤더는 다음과 같이 설정합니다. 이 예제는 브라우저가 Nginx에 직접 연결하는 구성이며, 추가 CDN·프록시가 있으면 방문자 IP를 별도로 복원해야 합니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:5173;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
}
```

Nginx는 방문자가 입력한 IP 헤더를 단일 접속 IP로 덮어써야 합니다. `proxy_add_x_forwarded_for`처럼 목록을 추가하는 설정은 이 서버의 단일 IP 검사에서 차단됩니다. Node 포트는 외부에 개방하지 않으며, 직접 개발 서버를 사용할 때는 `TRUSTED_PROXY_IPS`를 비워 둡니다. HTTPS 출처는 신뢰 프록시가 전달한 `X-Forwarded-Proto`로 확인합니다.

Pages에서 `/admin`의 정적 화면 자체는 보일 수 있지만, 관리자 데이터 조회·저장·재수집·로그 API는 항상 서버의 IP 제한을 적용합니다. VM이 관리자 화면도 제공하도록 하려면 `pnpm build`로 `dist`를 생성한 뒤 `pnpm start`로 실행합니다. 현재 서버 실행에 필요한 `tsx`·Vite가 개발 의존성에 있으므로 설치 시 개발 의존성을 제외하지 않습니다.

알림, 계정, ICS 내보내기는 이번 범위에 포함하지 않습니다.

## 몰아서 할 날짜 추천

캘린더 아래에서 선택한 게임·분류의 미완료 과제를 묶어 추천합니다. 버전은 제외하며 픽업은 별도 옵션으로 포함합니다. 마감 여유는 기본 24시간이며, 매일 또는 주말의 한국 시간 접속 시각을 지정할 수 있습니다. 제목 검색은 결과만 거르며 전체 추천 계산에는 영향을 주지 않습니다. 완료 체크와 수집 기간 변경은 즉시 다시 계산합니다.

한 번에 수행 가능한 과제는 유효 구간을 마감순으로 덮어 최소 방문 횟수를 계산합니다. 방문별 과제·게임 수·다음 마감을 표시하고 캘린더로 이동할 수 있습니다. 긴급 과제와 접속 시간·개방 조건 충돌은 따로 안내합니다.

수행 조건은 확인하지 않으니 주의 바랍니다. 출석 횟수·단계별 개방·누적 수행량·플레이 소요 시간은 계산하지 않으며, 일정 시작·종료와 마감 여유·접속 가능 시간만으로 추천합니다.

추천 시간 설정은 `subculture-calendar-planner` 브라우저 저장소에 보관합니다. 예전 수행 조건은 저장소 버전 2 이전 과정에서 제거하고 시간 설정만 유지합니다. 계산은 `src/features/planner/algorithm.ts`, 화면은 `components/PlannerPanel.tsx`, 회귀 검증은 `tests/planner.test.ts`에 있습니다.

## 버전 공지 자동 수집

서버 시작 시 유효 캐시가 없는 게임을 수집하고, 게임별 수집 완료 후 15분마다 자동 갱신합니다. 만료된 캐시 조회도 갱신하며 관리자 원본 재수집은 캐시·실패 대기를 건너뜁니다. 같은 게임의 진행 중 수집에는 합류하여 원본 요청을 중복 실행하지 않습니다.

HoYo는 한국어 업데이트 공지에서 시작·명시 종료를 읽고, 종료 정보가 부족하면 `/news/info?lang=ko-kr`와 `/news/events?lang=ko-kr`도 확인합니다. 세 게임의 공식 인게임 공지도 함께 대조합니다. 보상·개별 이벤트 종료를 버전 전체 기간으로 사용하지 않습니다. 명조 버전은 한국어 홈페이지·공식 라운지 공지로 수집합니다.

엔드필드는 공식 CMS `https://web-news.gryphline.com/api/bulletin?lang=ko-kr&code=arknights_endfield_official&page=1&pageSize=20` 및 `/api/bulletin/{id}`를 우선 사용합니다. 최대 3페이지의 최근 100일 공지에서 최대 20개 일정 관련 본문을 수집합니다. API 실패 시 기존 서버 렌더링 목록·본문으로 복구합니다. 개발자 통신의 다음 버전 개방 날짜도 확인하며 상세에서 종료 근거 링크를 제공합니다. 

공식 내부 CDN/CMS는 안정성이 보장된 공개 개발자 API가 아니므로 구조 변경 시 파서 보완이 필요합니다. 기본값은 공지에서 실제 종료를 확인했다는 뜻이 아니며, 수동 보정은 재수집보다 우선 유지됩니다.

명조 엔드콘텐츠는 기본 공개 JSON 경로에서 Asia 데이터를 자동 수집합니다. 로그인·피드 구축 없이 사용 가능합니다. 원본 명시 기간과 반복 규칙을 구분해 막대·상세·관리자에 표시합니다. 별도 WUWA_ENDGAME_FEED_URL은 구조화 경로에서 엔드콘텐츠가 누락됐을 때의 선택적 보완 경로입니다.

## 명조 구조화 수집

한국어 `https://wuwa.wiki/api/getconfig`, `/api/events/timeline/getcommon`, `/api/events/timeline/getversiondetail`을 먼저 사용합니다. 현재 데이터 버전은 config에서 조회하며 `lang=ko`, 버전 식별자, 서버 배열의 Asia 인덱스로 이름·기간을 읽습니다. 이벤트·픽업·버전·엔드콘텐츠에 같은 순서를 적용합니다.

누락은 공개 원본 `events.json`·`calendar.json`에 저장된 한국어 ID 사전을 연결해 보완합니다. 구조화 경로에서 제공하지 않는 웹 이벤트 등만 공식 한국어 CDN·라운지 공지 본문으로 보완합니다. 영구 개방 콘텐츠에는 임의 종료일을 만들지 않습니다.

로드맵의 울림의 영역(10/15 05:00–10/22 05:00), 흩날리는 선율(11/04 05:00–11/11 05:00)은 구조화 API로 수집합니다. 요약·개별 공지의 제목 차이로 중복되던 난투극·보물찾기를 한 건으로 합칩니다. 버전은 전반·후반이 연속인 경우만 전체 기간으로 합치며, 명조 3.7은 11/12 05:00 종료 경계로 반영합니다. 시각은 한국 시간입니다.

`WUWA_WIKI_API_BASE`, `WUWA_PUBLIC_EVENTS_URL`, `WUWA_PUBLIC_CALENDAR_URL`은 기본 공개 경로를 변경하는 선택적 환경 변수입니다. `WUWA_ENDGAME_FEED_URL`은 구조화 수집에서 엔드콘텐츠가 빠졌을 때의 선택적 보완이며 사용자 인증·피드 구축은 필요하지 않습니다. 공개 커뮤니티 자료의 근거를 막대·상세·관리자에 표시합니다.

## 비한국어 데이터의 한국어 표시

HoYo 3종의 한국어 API 성공 결과에서 콘텐츠 ID·유형과 한국어 이름을 `.cache/{game}-names.json`에 자동 저장합니다. 한국어 구조화 API 성공 시에도 영어 API를 대조하여 누락된 항목·기간을 먼저 보완합니다. 한국어 유효 기간은 유지하며, 한국어 API 실패 시 영어 API의 동일 ID에 저장된 한국어 제목을 적용합니다. 픽업은 캐릭터/무기 ID 조합으로 식별하여 같은 배너 슬롯이 다른 픽업으로 바뀌어도 예전 이름을 붙이지 않습니다. 원신 ID 0 엔드콘텐츠는 `type_name`도 식별에 사용합니다.

대응 이름이 없는 일정은 `한국어 이름 확인`으로 표시하고 원문·대상 일정 ID를 관리자 확인 항목에 기록합니다. 원문 외국어 설명은 달력에 그대로 노출하지 않습니다. 관리자에서 제목을 보정하고 한국어 표시를 선택하면 해당 이름을 다음 주기에도 적용하며, 보정 해제 시 해당 학습 이름을 제거합니다. 외부 번역 서비스·추가 계정·번역 비용은 사용하지 않습니다. 고유명사를 임의로 기계 번역하지 않습니다.

공개 데이터는 게임 내 규칙 변경을 즉시 보장하지 않습니다. 서버 자동 수집·만료된 캐시 조회·관리자 재수집으로 갱신합니다.

## 수집 스케줄러와 실행 로그

Node 서버가 실행 중일 때 게임별 실제 수집 완료부터 기본 15분 뒤 다시 수집합니다. 실패하면 이전 데이터를 유지하고 해당 게임의 재시도 간격을 30분부터 최대 4시간까지 늘립니다. 정상 게임의 갱신은 계속됩니다. 절전에서 돌아오면 누락된 횟수를 모두 반복하지 않고 한 번 수집하며, 서버 종료 시 타이머를 해제합니다. 자동화에는 서버 프로세스가 계속 실행되어 있어야 합니다.

`/admin`의 ‘수집 로그’ 탭에서 게임·상태·원인을 필터하고 최근 성공/실패·다음 실행 예정 시각을 확인할 수 있습니다. 시작/예약/수동/캐시 만료 수집은 실제 원본 요청 단위로 기록하고, 캐시 재사용과 진행 중 수집에 합류한 요청은 중복 기록하지 않습니다. 화면은 15초마다 로그를 다시 조회합니다.

로그는 `.cache/collection-logs/YYYY-MM-DD.jsonl`에 UTC 날짜별로 저장하고 재시작 시 복원합니다. 최근 30일·최대 10,000건·전체 8MiB 중 가장 작은 범위로 보관합니다. 이전 서버에서 중단된 실행은 중단 기록으로 복구합니다. 로그 저장 실패는 수집 상태와 별도로 표시합니다. `/api/admin/logs`는 허용된 IP의 관리자 전용이며 페이지당 30건을 제공합니다.

수집 개수는 제공자가 반환한 일정 후보 수, 병합 개수는 공통 중복 병합 후 개수입니다. 추가·변경·삭제는 ID 기준 후보이며, 출처 장애로 누락된 일정의 삭제를 확정하지 않습니다. 원본 전체 응답·토큰·내부 예외 메시지는 로그에 노출하지 않습니다. 여러 서버 인스턴스에서 운영하려면 단일 스케줄러 실행 또는 별도 잠금이 필요합니다.

수집 경로별 초기 조사는 `docs/source-audit.md`, 후속 구현과 검증 결과는 `docs/wuwa-implementation.md`를 참고하세요.

## 수집 우선순위

한국어 구조화 API → 원본 구조화 API와 한국어 이름 연결 → 공지 API 본문 파싱 → API 실패 시 공식 HTML 순서입니다. HoYo 3종 및 엔드필드 버전은 SRA 영어 구조화 API를 공식 한국어 버전 시작과 대조하며, 적용 가능한 명시 종료는 42일·날짜 단위 추정보다 우선합니다. 엔드필드 활동 후보는 안정된 한국어 이름·글로벌 Asia 대응을 확인하지 못한 경우 공식 CMS 본문을 사용합니다. SRA 경로는 SRA_API_BASE로 변경 가능합니다. 상세 경로·현재 결과·예외는 docs/collection-priority.md에 기록했습니다.
